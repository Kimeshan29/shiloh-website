  • Every test case classified as Positive, Negative, or Edge at generation time
  • Traceable via a source reference back to the exact requirement it came from

// COVERAGE BOT & AI EDITING

Ask about your test cases. Fill the gap in two clicks.

"Ask about your test cases" answers questions like this strictly from your real cases, citing the exact TC-00N cases that support the answer. When coverage is missing, it proposes a ready-to-use test case with a one-click Add button.

  • Grounded answers only — the bot never invents coverage that isn't there
  • Any test case or whole sub-feature can be edited with a natural-language instruction
  • Edits are previewed first, applied only on confirmation
  • The Coverage dashboard closes the loop — unclassified cases, never-executed cases, missing negative/edge coverage

// REPORTING & COVERAGE

Reporting is generated, not written.

Confidence comes from a system that can't flatter itself.

Per automated run

Pass/fail/skip counts and durations, plus AI root-cause analysis on every failure: probable cause, contributing factors, suggested fix, confidence score, and a classification — real bug, flaky, environment, or bad test data.

Executive report per run

Plain-English summary, key risks, recommendations, and trend versus the prior run — exportable to PDF for the people who don't open the dashboard.

Per manual round

CSV export and a formatted PDF execution report — project, platform, round, per-case status, type, and notes.

Coverage dashboard

Case-type mix is visible — a suite that only tests happy paths is immediately obvious. Gaps are surfaced, not hidden: 88% never-run shows as 88% never-run.

Evidence trail

Manual executions attach screenshots and recordings. Automated failures capture screenshots. Every defect carries both.

Alerts

Email notification on run completion, so nobody has to poll a screen waiting for results.

How the AI stays honest: the coverage bot answers only from real cases and cites their IDs. Coverage insights are generated from deterministically computed counts — the AI narrates the numbers, it never produces them. Defect analysis links to the actual failing result, with its stack trace and screenshot.

// DEVOPS & AUTOMATION

Anything that can curl can trigger a run.

Runs are dispatched via plain REST — POST /api/runs with a suiteId — including from a CI job. The agent is a portable standalone binary that connects outbound over websockets, so there are no inbound firewall rules to negotiate.

  • Install the agent on a build machine, a QA laptop, or a VM
  • Flows chain suites into regression pipelines, also dispatchable via API
  • Agent state reconciles on API restart — a dead agent can never silently absorb a dispatched run
APIPOST /api/runs
curl -X POST https://api.pulse.shiloh/runs \
  -H "Authorization: Bearer $TOKEN" \
  -d '{"suiteId":"checkout-regression"}'
→ 202 Accepted · dispatched to qa-agent-04
// WHERE WE ARE TODAY

The honest current gaps.

We'd rather tell you what's not built yet than have you find out mid-engagement.

▲Test types are a suite-naming convention today, not a field.
▲CI dispatch works but authenticates as a user, not a machine token yet.
▲No scheduler yet — every run is human- or API-triggered.
▲One agent per run today — no parallel fan-out yet.
▲Android only on mobile — iOS is a planned framework extension.
